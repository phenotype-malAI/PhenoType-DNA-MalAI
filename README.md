# PHENOTYPE

**Behavioural DNA Framework for Malware Attribution**

> Classify malware by what it does, not what it looks like.

PHENOTYPE encodes Windows API call sequences (from CAPE Sandbox dynamic analysis) into 256-dimensional L2-normalised behavioural fingerprints using a Transformer encoder trained with Supervised Contrastive Loss (SupCon). At inference, cosine similarity against per-family centroids either attributes a sample to a known family or labels it **UNKNOWN**. Open-world rejection needs no retraining and no separate detection module.

**[Research Paper](paper/phenotype_malai_2026.pdf)**

---

## Headline results (5 random seeds, mean ± std)

| Metric | Value |
| --- | --- |
| Closed-world accuracy (argmax, 5 families, 290 test samples) | 71.5 ± 1.5% (range 70.3–74.1%) |
| Macro F1 | 0.724 ± 0.018 |
| Open-world rejection (250 samples, 5 unseen families, θ = 0.986) | 84.6 ± 4.4% (range 77.2–87.6%) |
| Known-vs-novel AUROC (seed-42 run) | 0.853 |

At the deployed threshold θ = 0.986 the known-sample true-positive rate is only **0.66** (FPR 0.13). Roughly a third of correctly classifiable known samples are also rejected as UNKNOWN. Closed-world accuracy above is computed with argmax and no rejection, so it does not show this cost. Operators can move along the ROC curve without retraining.

Every number above is regenerated by `multi_seed_eval.py` (seeds 0–4). Seed sensitivity in open-world rejection is driven mostly by Amadey, whose behaviour sits close to the Redline centroid.

## Open-world comparison against baselines

All baselines use the same splits, the same 250 held-out samples, and the same calibration protocol (validation split only). Numbers are open-world rejection over seeds 0–4. `significance_test.py` runs paired tests across seeds (SupCon vs. each baseline).

| Method | Rejection (mean) | Per-seed range | Paired t-test p | Notes |
| --- | --- | --- | --- | --- |
| **PHENOTYPE (SupCon + cosine θ)** | **84.6%** | 77.2–87.6 | — | |
| MSP-thresholded CrossEntropy | 80.3% | 73.2–90.4 | **0.37** (not significant) | Max-softmax threshold (Hendrycks & Gimpel style) |
| OpenMax (Bendale & Boult) | 38.8% | 35.6–43.2 | 0.0001 | Weibull via `scipy` instead of `libmr`; CE logits |
| One-Class SVM (per family) | 34.5% | 9.2–46.8 | 0.0026 | RBF, ν = 0.05, on SupCon embeddings |
| CADE-style MAD distance rule | 16.1% | 0.8–36.8 | 0.0007 | CADE's decision rule on PHENOTYPE embeddings, not CADE's autoencoder |
| Energy-based OOD (Liu et al.) | 4.2% | 2.0–6.0 | <0.0001 | CE logits |

How to read this:

- PHENOTYPE clearly beats the four purpose-built open-set methods above.
- Against a well-tuned MSP-thresholded classifier the 4.2-point gap is **not statistically significant** at 5 seeds. The contrastive geometry gives a single global threshold that behaves consistently across families. It is not a categorical ability that classifiers lack.
- With n = 5 the smallest possible Wilcoxon signed-rank p-value is 0.0625, so that test cannot reach 0.05 here.
- The bootstrap in `significance_test.py` resamples the five seed-level rates, not the underlying 250 samples.
- `dmascl_baseline.py` is a joint CE + SupCon proxy (single run: 74.8% closed-world accuracy, 82.4% rejection). It is not a reproduction of a published method.

## Ablation (validation-selected checkpoints, 5 seeds)

| Model | Accuracy | F1 AgentTesla | F1 Lokibot | F1 Redline |
| --- | --- | --- | --- | --- |
| Transformer + SupCon | 70.69 ± 2.38% | 0.543 ± 0.073 | 0.557 ± 0.032 | 0.958 ± 0.008 |
| Transformer + CrossEntropy | 72.76 ± 2.61% | 0.586 ± 0.044 | 0.574 ± 0.066 | 0.963 ± 0.012 |
| Transformer + MeanPool | 69.65 ± 4.59% | 0.530 ± 0.043 | 0.542 ± 0.085 | 0.944 ± 0.041 |
| TF-IDF + LogReg | 72.55 ± 2.44% | 0.660 ± 0.023 | 0.494 ± 0.059 | 0.958 ± 0.020 |

Closed-world accuracy is statistically tied across variants, and a TF-IDF baseline is competitive. The Transformer does not win on accuracy. What SupCon adds is a usable embedding geometry for thresholded rejection.

`ablation.py` trains its own SupCon variant, so its accuracy (70.7%) differs slightly from the main pipeline's `train.py` runs (71.5%).

## Adversarial robustness (seed-42 SupCon vs. CrossEntropy, closed-world accuracy)

| Perturbation | Severity 0.0 | 0.1 | 0.3 |
| --- | --- | --- | --- |
| Insertion: SupCon / CE | 74.8 / 73.8 | 75.9 / 56.9 | **70.7 / 46.2** |
| Deletion: SupCon / CE | 74.8 / 73.8 | 72.1 / 72.1 | 67.6 / 67.2 |
| Reordering: SupCon / CE | 74.8 / 73.8 | 73.8 / 74.8 | 72.4 / 72.1 |

SupCon is clearly more robust under random API insertion. Under deletion and reordering the two models are close, and reordering is noisy and non-monotonic. Full results are in `outputs/adversarial/`.

## Architecture

```
Token Sequence (1,200 × int64)
        │
   Embedding  (vocab = 100 → d = 128, padding_idx = 0)
        │
   Sinusoidal Positional Encoding
        │
   4 × TransformerEncoderLayer
       (d_model=128, nhead=8, d_ff=512, GELU, Pre-LN, dropout=0.1)
        │
   Attention Pooling  (single learnable query vector)
        │
   Linear (128 → 256)  +  L2 Normalise
        │
   Behavioural Fingerprint  (256-dim, unit hypersphere)
        │
   Cosine Similarity vs 5 Family Centroids
        ├─ score ≥ 0.986  →  Attributed family
        └─ score  < 0.986  →  UNKNOWN
```

**Loss:** Supervised Contrastive Loss (`τ = 0.07`) · **Optimiser:** AdamW (`lr=3e-4`, `weight_decay=1e-4`) · **Schedule:** linear warm-up (10%) → cosine decay · **Sampler:** StratifiedBatchSampler (all 5 families in every batch of 64) · ~680K parameters, 2.7 MB.

## Quickstart

```bash
# 1. Install
pip install -r requirements.txt        # scipy comes in with scikit-learn

# 2. Train (requires final_dna_v2.csv, see Dataset)
python train.py --csv final_dna_v2.csv --out_dir outputs/run1 --device cuda --epochs 100

# 3. Attribute a sample
python attribute.py --csv_row final_dna_v2.csv --row_idx 42 \
    --encoder outputs/run1/behaviour_encoder.pt \
    --centroids outputs/run1/family_centroids.pt
```

## Reproducing the paper's results

Run from the repo root. A GPU is strongly recommended (Colab free tier works). Each step depends on the ones before it.

```bash
# A. Five-seed main results (trains 5 models; writes outputs/multi_seed/)
python multi_seed_eval.py --csv final_dna_v2.csv --seeds 0 1 2 3 4 --device cuda

# B. Five-seed ablation + MSP-thresholded CrossEntropy baseline (retrains variants)
python multi_seed_ablation.py --csv final_dna_v2.csv --seeds 0 1 2 3 4 --epochs 50 --device cuda
#    The OpenMax / energy / adversarial steps need a CrossEntropy checkpoint at
#    outputs/ablation/crossentropy_model.pt. Add this line to ablation.py after the CrossEntropy
#    model's `load_state_dict(best_state)` (main() has ce_model in scope), then run once:
#        torch.save(ce_model.state_dict(), out_dir / 'crossentropy_model.pt')
#        python ablation.py --csv final_dna_v2.csv --out_dir outputs/ablation

# C. Post-hoc baselines (no training; repeat for --seed 0..4)
for s in 0 1 2 3 4; do
  python cade_baseline.py        --csv final_dna_v2.csv --seed $s --device cuda \
      --encoder outputs/multi_seed/seed_$s/behaviour_encoder.pt \
      --centroids outputs/multi_seed/seed_$s/family_centroids.pt \
      --out_dir outputs/cade_baseline/seed_$s
  python oneclass_svm_baseline.py --csv final_dna_v2.csv --seed $s --device cuda \
      --encoder outputs/multi_seed/seed_$s/behaviour_encoder.pt \
      --centroids outputs/multi_seed/seed_$s/family_centroids.pt \
      --out_dir outputs/oneclass_svm_baseline/seed_$s
  python openmax_baseline.py     --csv final_dna_v2.csv --seed $s --device cuda \
      --ce_checkpoint outputs/ablation/crossentropy_model.pt \
      --out_dir outputs/openmax_baseline/seed_$s
  python energy_baseline.py      --csv final_dna_v2.csv --seed $s --device cuda \
      --ce_checkpoint outputs/ablation/crossentropy_model.pt \
      --out_dir outputs/energy_baseline/seed_$s
done

# D. Significance tests (reads everything above)
python significance_test.py --multi_seed_csv outputs/multi_seed/multi_seed_results.csv

# E. Single-run analyses (seed 42): ROC, adversarial, joint-loss proxy
python compute_open_world_roc.py --test_scores outputs/single_run/test_scores.csv \
    --held_out_results outputs/single_run/held_out_results.json --out_dir outputs/single_run
python adversarial_eval.py   --help     # see flags
python dmascl_baseline.py    --help
```

Notes:

- The CrossEntropy checkpoint in `outputs/ablation/` was saved with the one-line patch above. The unpatched `ablation.py` does not save it, so the baselines cannot be re-run from a fresh clone without it.
- The OpenMax and energy baselines load a single CrossEntropy checkpoint, so across seeds only the train/val/test split changes, not the classifier weights.
- GPU training is not bit-reproducible across sessions even with a fixed seed, because deterministic CUDA algorithms are not enabled. That is why headline numbers are five-seed averages.
- `--seed` must match the seed the checkpoint was trained with, because it selects the train/val/test split.

## Limitations

- **Small, single-source data:** 1,932 samples, 5 families, one sandbox (CAPE), one dataset (WinMET). Centroid quality suffers for Formbook (272 samples).
- **No temporal split:** train and test come from the same database, so distribution shift between collection periods is not measured.
- **Names only:** without call arguments, AgentTesla and Lokibot cannot be separated.
- **Coverage cost of rejection:** at θ = 0.986 about a third of correctly classifiable known samples are rejected as UNKNOWN (TPR 0.66).
- **No benign-software evaluation:** PHENOTYPE has only been tested against other malware families, never against goodware.
- **Rejection advantage over MSP-thresholding is not significant** at 5 seeds (see the comparison table above).
- **Baselines are re-implementations of decision rules** on PHENOTYPE's embeddings or CE logits, not reproductions of the original systems' encoders.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `TSNE.__init__() unexpected keyword 'n_iter'` | scikit-learn ≥ 1.5: use `max_iter=` in `visualise.py` |
| Baseline script fails to load a checkpoint | Check that `--seed` matches the checkpoint's training seed |
| Numbers differ slightly from the paper on rerun | Expected: GPU training is not bit-reproducible; compare against the five-seed mean ± std |
| All samples predicted as one family | Check `StratifiedBatchSampler` and class weights in `dataset.py` |
| NaN loss | Reduce LR; confirm gradient clipping (`max_norm=1.0`) |
